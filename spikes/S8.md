# S8 — Can the agent run as a host process on DSM 7?

**Status: NOT RUN — needs the NAS shell.** No launchd on DSM, so the boot story
is Task Scheduler (boot-up trigger) plus the keepalive loop in
`deploy/dsm/a2a-goose-boot.sh` (§8). That script is written and `bash -n`-clean,
but nothing has proven it on the real box.

## What to prove

1. Task Scheduler can be pointed at `a2a-goose-boot.sh` with a boot-up trigger,
   running as **goose's user, not root** (hard constraint #9's neighbourhood).
2. The loop actually restarts the launcher after a kill (`kill` the launcher,
   watch the wrapper bring it back within `RESTART_DELAY`).
3. A DSM **package** upgrade or restart does not orphan the wrapper — i.e. the
   process survives what it needs to, and comes back after a reboot.
4. Logs land somewhere retrievable (`logger` → `/var/log/messages`, plus stderr).

## Method

On the NAS, install the Task Scheduler entry, reboot, then:
`pgrep -af a2a-goose` → kill the launcher → wait > `RESTART_DELAY` → `pgrep` again.
