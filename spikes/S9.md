# S9 — Can the LiteLLM container reach the agent at its `card.url`?

**Status: NOT RUN — needs the NAS shell.** This is the networking half of §6.2:
LiteLLM registers an agent by its card URL and (per [S5](../spikes/S5.md)) fills
in the real card later, or not at all, if the URL is unreachable.

## What to prove

- From **inside the LiteLLM container**, `curl` the agent's card at the
  `card.url` we register. A container's `127.0.0.1` is not the host's, so
  `card.url` must be a host-reachable address even though `server.bind` is
  loopback.
- The timeout matters: registration is best-effort, so an unreachable card is a
  **silent** default (`skills: [{id: "chat"}]`), not an error. Prove the
  reachable case so we never debug this from the LiteLLM side.
- Record the exact hostname/IP to use on the NAS, and how it differs from the
  Mac Studio's Tailscale name (`mac-studio.tail86fd19.ts.net`).
