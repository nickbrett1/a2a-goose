# S1 — Which `goose serve` invocation?

**Plan (§4):** bare (`127.0.0.1:3284`, `/acp`) or `--platform desktop
--enable-scheduler`? *Start both; diff exposed methods. Pin whichever exposes the
full ACP surface.*

## Method

Started both against goose 1.50.0 and diffed `initialize`:

```
goose serve --port 3284 --dangerously-unauthenticated
goose serve --port 3285 --platform desktop --enable-scheduler --dangerously-unauthenticated
```

then, for each:

```
curl -sS -X POST http://127.0.0.1:$PORT/acp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":0,"method":"initialize","params":{"protocolVersion":1,"clientCapabilities":{}}}'
```

`--dangerously-unauthenticated` is a local-probe convenience only. The real
hosts use `GOOSE_SERVER__SECRET_KEY` and the agent sends `X-Secret-Key`.

## Evidence

Both ports returned byte-identical capability objects:

```json
{"protocolVersion": 1,
 "agentInfo": {"name": "goose", "version": "1.50.0"},
 "agentCapabilities": {
   "loadSession": true,
   "promptCapabilities": {"image": true, "audio": false, "embeddedContext": true},
   "mcpCapabilities": {"http": true, "sse": false},
   "sessionCapabilities": {"list": {}, "delete": {}, "close": {}},
   "auth": {},
   "_meta": {"goose": {"recipeParameterScopes": {}, "localInference": {}}}},
 "authMethods": [{"id": "goose-provider", ...}]}
```

The diff is empty: `--platform desktop --enable-scheduler` adds scheduler
behaviour, not ACP surface.

## Verdict

**PASS — pin the bare invocation**: `goose serve` on `127.0.0.1:3284`, endpoint
`/acp`. That is `--platform cli`, the default, and it is the smaller thing to
explain on a host.

`--enable-scheduler` is deliberately *not* used: nothing in this project runs
scheduled recipes, and enabling it would let a host's own schedule fire goose
sessions behind the node agent's back — with no `contextId`, so nothing in the
agent's map or in LiteLLM's per-thread accounting would know about them.

## What it changes

Nothing in the plan; S1 was the "don't inherit a default" check, and the default
is the right answer. It is now the documented invocation for both hosts.
